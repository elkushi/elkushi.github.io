04 · How I build

I break things for work, so I build them locked down

I do part-time penetration testing of my company's websites and SMS platform against an OWASP checklist. That work is why the apps below start closed and open only where they have to. Every line here is enforced in code, not promised in a policy.

  • AI agents get an allowlist of tools, never open shell access. An agent that can run commands is the attack surface.
  • Uploads and file paths are checked, so nobody can read files outside the app. Tests try /etc/passwd and ../ and expect a refusal.
  • The audit app refuses private and internal addresses and re-checks after every redirect, so a stranger cannot make my server fetch my own network.
  • Servers run HTTPS and key-only SSH, with hashed passwords and rate-limited sign-in.
  • Containers run as a normal user, not root, with Linux capabilities dropped.
  • Keys stay in .env, and every repository is scanned for secrets before it goes public.

Tools: nmap, Wireshark, Burp Suite, OWASP testing, TryHackMe. I also wrote system-audit, a Bash tool that checks a Linux server for the misconfigurations I keep finding.

Do you take projects or full-time roles?

Both: fixed-scope projects, and longer-term roles in AI product and automation. For a project, pick a service above or tell me what you need.

What does “AI that checks its own work” mean?

The model’s answer passes checks before anyone sees it. A JSON schema checks its shape, validators compare it with your sources, and a QA step can reject it. A wrong answer is caught, not shipped. A chatbot that isn’t sure hands the question to a person.
