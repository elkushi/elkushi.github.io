إطار WAT: كيف أجعل Claude Code موثوقًا

يقسّم إطار WAT مشروع الذكاء الاصطناعي إلى ثلاث طبقات: مسارات العمل (Workflows) تحدّد ما يجب فعله، والوكيل (Agent) يتخذ القرارات، والأدوات (Tools) تنفّذ العمل. كل مشاريع الذكاء الاصطناعي في هذا الموقع مبنية بهذه الطريقة. في هذا المقال: كيف يعمل، والقواعد التي أتبعها لأحصل منه على أفضل نتيجة.

المشكلة التي يحلّها

اطلب من وكيل ذكاء اصطناعي أن ينجز وحده مهمة من عشر خطوات، وغالبًا سيصيب في معظمها. وهنا تكمن المشكلة. إذا كانت دقة كل خطوة 90%، فإن خمس خطوات متتالية لا تصحّ كلها إلا في 59% من المرات. تتراكم الأخطاء، ويتحدث الوكيل بالثقة نفسها حين يخطئ.

الحل ليس في تعليمات (prompt) أذكى، بل في ألّا تطلب من النموذج ما يتقنه الكود أكثر منه. النموذج بارع في التقدير: ما المهم، وماذا يقول، وما الذي يجرّبه بعد ذلك. أما الكود فبارع في تكرار الشيء نفسه بالطريقة نفسها كل مرة: جلب صفحة، والعدّ، والتحقق، وإنشاء ملف PDF.

الطبقات الثلاث

W

مسارات العمل

تعليمات مكتوبة بـ Markdown في المجلد workflows/. يحدّد كل منها الهدف، والمدخلات، والأدوات المطلوبة، وشكل النتيجة، وطريقة التعامل مع الحالات الاستثنائية. تُكتب كما لو كنت تشرح المهمة لزميل في الفريق.

A

الوكيل

هو Claude Code. يقرأ مسار العمل، ويتخذ القرارات، ويشغّل الأدوات بالترتيب الصحيح، ويعالج الأخطاء، ويسأل حين لا يتضح له أمر. يربط الهدف بالتنفيذ دون أن ينجز كل خطوة بنفسه.

T

الأدوات

سكربتات Python في المجلد tools/ تقوم بالعمل الفعلي: استدعاءات API، وتنظيف البيانات، والملفات، وقواعد البيانات. سريعة، وقابلة للاختبار، وتعطي النتيجة نفسها في كل مرة. وتُحفظ المفاتيح في .env.

يبدو المشروع النموذجي هكذا:

CLAUDE.md      # the rules: you are the agent, this is how you operate
workflows/     # Markdown instructions: what to do and how
tools/         # Python scripts that do the work
schemas/       # JSON contracts between the agent and the tools
.tmp/          # intermediate files, safe to delete
.env           # API keys, never committed

كيف تستخدمه بالشكل الصحيح

الهيكل وحده لا يجعل المشروع موثوقًا. ما يجعله كذلك هو القواعد التالية، وكل واحدة منها مأخوذة من مشروع أطلقته فعلًا.

  1. اكتب مسار العمل قبل الكود. إذا لم تستطع أن تكتب الهدف والمدخلات وما يعنيه «الانتهاء»، فلن يخمّنها الوكيل أيضًا.
  2. دع النموذج يقرّر والكود ينفّذ. كل خطوة يجب أن تعطي النتيجة نفسها في كل مرة هي أداة. الجلب والعدّ والدمج ورسم المخططات والإخراج (rendering) لا تُترك للنموذج أبدًا.
  3. ضع بينهما عقدًا واضحًا. يكتب الوكيل JSON، ويتحقق منه JSON Schema قبل تشغيل أي خطوة بطيئة أو مكلفة. في مولّد الفيديو الذي بنيته، إذا فشلت لوحة القصة (storyboard) في التحقق، فلن تصل إلى مرحلة الإخراج أبدًا.
  4. أضف بوابة تستطيع أن ترفض. في مسار البحث الذي بنيته، يمنع مدقّق إنشاء ملف PDF إذا كان أي ادعاء بلا مصدر أو أي رابط معطّلًا. تُشرح القواعد للذكاء الاصطناعي، والكود هو الذي يفرضها.
  5. توقّف لمراجعة بشرية عند نقاط محددة. يتوقف مسار البحث عند أربع نقاط تحقق، منها اعتماد قائمة المنافسين قبل أن يبدأ تسعة وكلاء بحث عملهم. إصلاح الخطأ في البداية رخيص، وفي النهاية مكلف.
  6. أعد استخدام الأدوات قبل كتابة أدوات جديدة. يبحث الوكيل في tools/ أولًا، ولا تُكتب سكربتات جديدة إلا إذا لم يناسب شيء موجود، فتبقى مجموعة الأدوات صغيرة ومختبَرة.
  7. ضع حدًا لمحاولات الإعادة. في مولّد الفيديو، يعيد وكيل المراجعة إما SHIP أو قائمة إصلاحات، وله جولتان على الأكثر، ثم يتوقف التشغيل. والوكيل الذي يستطيع أن يدور بلا نهاية سيدور بلا نهاية.
  8. حوّل كل عطل إلى مسار عمل أفضل. حين تتعطل أداة، يصلحها الوكيل، ويختبر الإصلاح، ويدوّن ما تعلّمه في مسار العمل: حدّ لعدد الطلبات، أو واجهة API بطيئة، أو موقع يحجب البرامج الآلية. فلا يصطدم التشغيل التالي بالعقبة نفسها.
  9. اسأل قبل أن تنفق المال. إذا تطلّب الإصلاح إعادة تشغيل استدعاءات API مدفوعة، يسأل الوكيل أولًا.
  10. امنح الوكيل الأدوات التي يحتاجها فقط. قائمة محددة من السكربتات المسموح بها، لا وصول مفتوح إلى سطر الأوامر. وتبقى المفاتيح السرية في .env، خارج git.

ملف CLAUDE.md للبداية

يقرأ Claude Code ملف CLAUDE.md في بداية كل جلسة، ولذلك نضع الإطار فيه. هذه نسخة مختصرة:

# Agent instructions

You work inside the WAT framework.
- Workflows: before acting, read the matching file in workflows/.
- Agent: you decide and run the tools in order.
  Don't do by hand what a tool already does.
- Tools: scripts in tools/. Look for an existing tool
  before writing a new one.

When a tool fails: read the full error, fix the tool,
test it again, and write what you learned into the workflow.
Ask before re-running anything that costs money.
Don't overwrite a workflow without asking.

متى لا تحتاج إليه

السؤال العابر أو التعديل السريع لا يحتاجان إلى ثلاث طبقات. يؤتي WAT ثماره حين تتكرر المهمة، أو حين تكثر خطواتها، أو حين يكون للخطأ ثمن: تقرير يُرسَل إلى عميل، أو فيديو يُنشر باسم علامة تجارية، أو فحص سيتخذ أحدهم قرارات بناءً عليه.

شاهده في مشاريع حقيقية

  • مسار عمل بحثي مع مدقّق: 61 صفحة، ونحو 190 مصدرًا، ولا ادعاء بلا مصدر.
  • مولّد الفيديو والصور بالذكاء الاصطناعي: فحص مخطط البيانات، وخطوة لضمان الجودة، ومراجِع له جولتان على الأكثر.
  • فحص المواقع لـ Google وللبحث بالذكاء الاصطناعي: الفحوص المبنية على قواعد ثابتة تعمل كأدوات، ووكلاء Claude يتولّون التحليل.
  • الكود: github.com/elkushi/claude_vibe_coding_projects
