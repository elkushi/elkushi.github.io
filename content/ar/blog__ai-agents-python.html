وكيل الذكاء الاصطناعي: ما هو، وكيف تبنيه، ولماذا Python

وكيل الذكاء الاصطناعي نموذج لغوي يستطيع أن ينفّذ: يختار أداة، ويشغّلها، ويقرأ النتيجة، ثم يقرّر ما يفعله بعد ذلك. في هذا المقال: ما يعنيه ذلك بكلمات بسيطة، ووكيل يعمل في نحو 40 سطرًا من Python، والقواعد التي تمنعه من الخطأ. كل قاعدة منها مأخوذة من وكيل أطلقته فعلًا.

ما هو وكيل الذكاء الاصطناعي

روبوت المحادثة يجيب. أما الوكيل فينفّذ. تعطيه هدفًا، لا سؤالًا، وهو يحدّد الخطوات بنفسه.

لكل وكيل الأجزاء الأربعة نفسها:

  • نموذج يتخذ القرارات: Claude، أو GPT، أو Gemini، أو نموذج يعمل محليًا.
  • أدوات مسموح له باستخدامها: البحث في الويب، وقراءة ملف، والاستعلام من قاعدة بيانات، وإرسال بريد إلكتروني. كل أداة دالة عادية في كودك.
  • حلقة تكرار (loop). يطلب النموذج أداة، فيشغّلها كودك، وتعود النتيجة إلى النموذج، فيقرّر الخطوة التالية.
  • شرط توقف. تنتهي المهمة، أو يفشل فحص، أو يستنفد الوكيل عدد الخطوات المسموح له.

النموذج لا يشغّل أي شيء بنفسه. كل ما يفعله أن يقول «استدعِ هذه الأداة بهذه المدخلات». وكودك هو الذي يقرّر هل ينفّذ ذلك أم لا. هذه أهم حقيقة عن الوكلاء، وهي ما يجعل بناءهم آمنًا.

روبوت محادثة، أم مسار عمل، أم وكيل؟

لا تحتاج كل ميزة ذكاء اصطناعي إلى وكيل. اختر أبسط خيار ينجز المهمة.

النوعمن يحدّد الخطواتمتى تستخدمه
روبوت محادثةلا أحد: سؤال واحد وجواب واحدللإجابة عن الأسئلة من محتواك
مسار عملأنت، في الكود، بترتيب ثابتحين تكون الخطوات هي نفسها كل مرة، مثل تقرير أسبوعي
وكيلالنموذج، خطوة بعد خطوةحين تعتمد الخطوة التالية على ما وجدته الخطوة السابقة، مثل البحث

معظم مشاريعي تجمع بين مسار العمل والوكيل. الكود ينفّذ الخطوات الثابتة، والوكيل لا يقرّر إلا حيث يلزم التقدير. كتبت عن هذا التقسيم في مقال إطار WAT.

وكيل في نحو 40 سطرًا من Python

يستقبل هذا الوكيل قائمة روابط، ويخبرك أيها معطّل. لديه أداة واحدة هي check_url، وهي دالة Python عادية. النموذج يقرّر أي العناوين يفحص، ويكتب الملخص.

import json
import urllib.request

import anthropic

client = anthropic.Anthropic()  # reads ANTHROPIC_API_KEY from the environment


def check_url(url: str) -> str:
    """The tool: a normal function. The model never runs it, we do."""
    if not url.startswith("https://"):
        return json.dumps({"url": url, "error": "only https addresses are allowed"})
    try:
        with urllib.request.urlopen(url, timeout=10) as r:
            return json.dumps({"url": url, "status": r.status})
    except Exception as e:
        return json.dumps({"url": url, "error": str(e)})


TOOLS = [{
    "name": "check_url",
    "description": "Fetch one https address and return its HTTP status, or the error.",
    "input_schema": {
        "type": "object",
        "properties": {"url": {"type": "string"}},
        "required": ["url"],
    },
}]

messages = [{"role": "user", "content":
             "Check these pages and tell me which are broken: "
             "https://example.com, https://example.com/missing-page"}]

for step in range(10):  # a hard cap: an agent that can loop forever will
    reply = client.messages.create(model="claude-sonnet-5-5", max_tokens=1024,
                                   tools=TOOLS, messages=messages)
    messages.append({"role": "assistant", "content": reply.content})
    if reply.stop_reason != "tool_use":
        print("".join(b.text for b in reply.content if b.type == "text"))
        break
    results = [{"type": "tool_result", "tool_use_id": b.id, "content": check_url(**b.input)}
               for b in reply.content if b.type == "tool_use"]
    messages.append({"role": "user", "content": results})

ثبّت المكتبة بالأمر pip install anthropic، واضبط مفتاح API، ثم شغّل الكود. في هذا الكود ثلاثة أشياء أهم من النموذج نفسه:

  • الأداة تتحقق من مدخلاتها بنفسها. ترفض أي عنوان ليس https. لا تثق أبدًا بأن النموذج سيلتزم بالقواعد التي كتبتها في التعليمات (prompt).
  • الوصف هو التوثيق. يقرأ النموذج وصف الأداة ليقرّر متى يستخدمها. والوصف الغامض يعطيك وكيلًا مرتبكًا.
  • للحلقة حدّ أقصى. عشر خطوات، ثم تتوقف، مهما حدث.

هذه هي الفكرة كلها. أُطر العمل مثل LangGraph أو CrewAI تضيف فوقها الذاكرة، وتعدّد الوكلاء، وإعادة المحاولة، لكن في داخل كل واحد منها هذه الحلقة نفسها.

كيف تبني وكيلًا يعمل فعلًا

العرض التجريبي أعلاه يعمل من المحاولة الأولى. أما الوكيل الحقيقي فعليه أن يعمل في المحاولة المئة أيضًا. هذه هي القواعد التي أتبعها:

  1. ابدأ من المهمة، لا من النموذج. اكتب الهدف، والمدخلات، وما يعنيه «الانتهاء»، قبل أن تكتب أي كود. إذا لم تستطع ذلك، فلن يخمّنه الوكيل.
  2. لا تعطه إلا الأدوات التي يحتاجها. قائمة محددة من الدوال المسموح بها، لا وصول مفتوح إلى سطر الأوامر. الوكيل في مولّد الفيديو الخاص بي يستطيع تشغيل سكربتات المشروع نفسه، وffmpeg، وبضعة أوامر للقراءة فقط. ولا شيء غير ذلك.
  3. دع الكود يفعل ما يتقنه أكثر من النموذج. الجلب، والعدّ، والدمج، والإخراج (rendering) مكانها أدوات Python. النموذج يقرّر، والأدوات تنفّذ.
  4. تحقّق من المخرجات بمخطط بيانات (schema). اجعل الوكيل يعيد JSON، وتحقّق منه قبل تشغيل أي خطوة بطيئة أو مكلفة. في مولّد الفيديو الخاص بي، إذا فشلت لوحة القصة (storyboard) في التحقق من JSON Schema، فلن تصل إلى مرحلة الإخراج أبدًا.
  5. أضف بوابة تستطيع أن ترفض. في مسار البحث الذي بنيته، يمنع مدقّق إصدار التقرير إذا كان أي ادعاء بلا مصدر أو أي رابط معطّلًا. تُشرح القواعد للوكيل، والكود هو الذي يفرضها.
  6. توقّف لمراجعة بشرية عند نقاط محددة. يتوقف المسار نفسه عند أربع نقاط تحقق، منها اعتماد قائمة المنافسين قبل أن يبدأ تسعة وكلاء بحث عملهم.
  7. ضع حدًا لمحاولات الإعادة. في مولّد الفيديو، يعيد وكيل المراجعة إما SHIP أو قائمة إصلاحات، وله جولتان على الأكثر.
  8. سجّل كل خطوة. احفظ كل استدعاء لأداة ونتيجته. حين يخطئ الوكيل، يُريك السجل في أي خطوة حدث الخطأ، وهناك تضع الإصلاح.

لماذا Python

تستطيع أن تبني وكيلًا بأي لغة برمجة. لكن معظم العمل يجري في Python، لأسباب عملية:

  • مكتبات الذكاء الاصطناعي تصل إلى Python أولًا. تنشر Anthropic وOpenAI مكتبات Python رسمية، وبدأت LangGraph وCrewAI وLlamaIndex وPydantic AI كلها مشاريعَ مكتوبة بـ Python.
  • الأداة مجرد دالة. كما يُظهر المثال، يمكن لأي دالة Python أن تصبح أداة. كل ما تستطيع Python فعله، يستطيع وكيلك فعله.
  • مكتبات الأدوات موجودة أصلًا. Playwright للمتصفحات، وpandas للبيانات، وrequests لواجهات API، وWeasyPrint لملفات PDF، وWhisper للكلام. معظم الأدوات التي تحتاجها لا تتطلب أكثر من بضعة أسطر تربط بين هذه المكتبات.
  • التحقق من المخرجات سهل. تحوّل Pydantic وjsonschema شرط «يجب أن يعيد النموذج هذا الشكل» إلى سطر واحد من الكود، يفشل بخطأ واضح.
  • الكود نفسه يصبح منتجًا. FastAPI تضع الوكيل خلف واجهة API على الويب، وDocker يجهّزه للنشر. لا حاجة إلى لغة ثانية.

هكذا يبدو التحقق بمخطط البيانات في Pydantic. إذا أغفل النموذج المصدر، يتوقف التشغيل بدل أن يُنشر الادعاء:

from pydantic import BaseModel, HttpUrl


class Claim(BaseModel):
    text: str
    source_url: HttpUrl  # no source, no claim


claim = Claim.model_validate_json(model_output)  # raises an error if anything is missing

مشاريعي الثلاثة القائمة على الوكلاء تتبع كلها هذا النمط: Claude يقرّر، وPython تنفّذ العمل وتتحقق منه.

متى لا تحتاج إلى وكيل

إذا كانت الخطوات هي نفسها دائمًا، فاكتب سكربتًا. السكربت أرخص وأسرع، ويعطي النتيجة نفسها في كل مرة. وإذا كنت تحتاج فقط إلى إجابات من محتواك، فروبوت المحادثة يكفي. استخدم الوكيل حين تعتمد الخطوة التالية فعلًا على ما وجدته الخطوة السابقة، وضع حوله فحوصًا تكشف أي خطوة خاطئة.

شاهده في مشاريع حقيقية

  • مولّد الفيديو والصور بالذكاء الاصطناعي: وكيل للاستراتيجية، ووكيل لكتابة السيناريو، ووكيل للمراجعة، مع أدوات Python، وفحص مخطط البيانات، وخطوة لضمان الجودة.
  • مسار عمل بحثي مع مدقّق: تسعة وكلاء بحث يعملون بالتوازي، وبوابة تمنع أي ادعاء بلا مصدر.
  • فحص المواقع لـ Google وللبحث بالذكاء الاصطناعي: زاحف (crawler) مكتوب بـ Python وفحوص قائمة على القواعد، مع خمسة وكلاء Claude Code للتحليل.
  • إطار WAT: كيف أقسّم العمل بين الوكيل والأدوات.
